## Описание

В задании была мини-игра с котом. На странице отображались счёт и цель, а справа находился блок с чит-кодами. Проблема была в том, что чит-коды были размыты и визуально не читались.

Так как категория задания была **Clientside**, сразу стало понятно, что искать нужно не на сервере, а в браузере: в HTML, CSS, JavaScript, DOM, cookies, localStorage или canvas.

## Основная идея

Данные не были зашифрованы и не были защищены серверной проверкой. Они уже находились на странице, но были скрыты визуально с помощью CSS-фильтра размытия.

То есть сайт пытался спрятать информацию только на стороне клиента.

## Ход решения

### 1. Открытие DevTools

Сначала я открыла инструменты разработчика в браузере через `F12`.

Во вкладке **Elements** начала смотреть HTML-структуру страницы и нашла блок с чит-кодами:

```html
<aside class="cheat-panel">
```

Внутри блока находился элемент `canvas`, на котором были нарисованы чит-коды.

### 2. Поиск причины размытия

В HTML было видно, что к `canvas` применён CSS-фильтр:

```html
<canvas class="cheat-copy-canvas" style="filter: blur(...);">
```

Это означало, что чит-коды не были удалены со страницы. Браузер просто применял к ним визуальный эффект размытия.

### 3. Отключение размытия

Дальше я перешла во вкладку **Console** и убрала CSS-фильтр:

```javascript
document.querySelector('.cheat-copy-canvas').style.filter = 'none';
document.querySelector('.cheat-copy-canvas').style.webkitFilter = 'none';
```

Также был скрывающий слой, который перекрывал область с кодами. Его можно было убрать так:

```javascript
document.querySelector('.cheat-cover').style.display = 'none';
```

После этого чит-коды стали видны на странице.

### 4. Прохождение игры

После удаления размытия я перезапустила игру и ввела найденные чит-коды. Это позволило выполнить условие задания и получить итоговый ответ.

Флаг в публичной версии writeup не указывается:

```text
flag{...}
```

## Почему это сработало

Сайт хранил важную информацию прямо в клиентской части. Размытие через CSS не является защитой, потому что пользователь может открыть DevTools и изменить стили страницы.

Такая ошибка часто встречается в простых web-задачах, где нужно проверить, действительно ли данные защищены, или они просто скрыты визуально.

## Использованные инструменты

- Browser DevTools
- вкладка `Elements`
- вкладка `Console`
- HTML / CSS
- JavaScript
- анализ DOM
- работа с `canvas`

## Краткий вывод

Задание показало базовую, но важную идею веб-безопасности: если данные уже находятся в браузере пользователя, то их нельзя считать защищёнными. Визуальное скрытие через CSS не заменяет настоящую серверную проверку доступа.
