## Описание

В задании был доступ к удалённому Linux-серверу по SSH. После подключения появлялась проверка с вводом одноразового пароля.

На первый взгляд нужно было узнать или подобрать OTP-код, но основная идея задания была не в подборе пароля, а в анализе того, как именно программа обрабатывает пользовательский ввод.

## Основная идея

В коде проверки использовалась команда `read` с флагом `-e`:

```bash
read -e -s -r -p 'One-time password: ' otp
```

Флаг `-e` включает режим `readline`. Это значит, что во время ввода можно использовать специальные сочетания клавиш `readline`.

Одно из таких сочетаний позволяет открыть текущую строку ввода во внешнем редакторе. А внешний редактор был задан через переменную окружения:

```bash
export EDITOR=/usr/bin/vim
```

Так как `vim` позволяет запускать команды операционной системы, через него можно было получить shell до завершения проверки OTP.

## Ход решения

### 1. Подключение по SSH

Сначала я подключилась к серверу по SSH с выданными учётными данными:

```bash
ssh user@host
```

В публичной версии writeup реальные адреса, логины и пароли не указываются:

```text
login: [redacted]
password: [redacted]
host: [redacted]
```

### 2. Анализ проверки OTP

После подключения программа просила ввести одноразовый пароль:

```text
One-time password:
```

Из условия и кода было понятно, что ввод обрабатывается через `read -e`.  
Это важная деталь, потому что `readline` поддерживает дополнительные действия во время ввода.

### 3. Открытие внешнего редактора

Во время ввода OTP я использовала сочетание клавиш:

```text
Ctrl + X, затем Ctrl + E
```

После этого текущая строка ввода открылась во внешнем редакторе `vim`.

### 4. Получение shell через vim

В `vim` можно выполнять команды операционной системы. Для этого я использовала командный режим:

```vim
:!/bin/sh
```

После выполнения этой команды открылась обычная командная строка Linux.

### 5. Проверка окружения

После получения shell я проверила, под каким пользователем работаю и какие файлы доступны:

```bash
id
pwd
ls -la
```

Также можно было выполнить поиск по формату флага:

```bash
grep -Rni "flag{" ~ 2>/dev/null
```

В реальном CTF использовался формат флага соревнования, но в публичном writeup он не указывается:

```text
flag{...}
```

## Почему это сработало

Проверка OTP была построена небезопасно, потому что пользователю разрешили использовать расширенные возможности `readline`, а внешний редактор был установлен как `vim`.

`vim` — это не только текстовый редактор. Из него можно запускать системные команды. Поэтому пользователь смог получить shell ещё до того, как программа завершила проверку одноразового пароля.
