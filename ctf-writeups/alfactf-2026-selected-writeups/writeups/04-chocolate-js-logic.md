## Описание

В задании был веб-магазин шоколада. На сайте отображался баланс пользователя, список товаров и возможность применить промокод.

На первый взгляд нужно было накопить деньги или найти правильный промокод, чтобы купить нужный товар. Но основная идея задания была в ошибке логики обработки баланса.

## Основная идея

Уязвимость была связана с особенностями JavaScript при работе с числами и строками.

В коде приложения баланс изменялся примерно по такой логике:

```javascript
session.balance += promo.amount;
```

Если `promo.amount` является числом, баланс увеличивается корректно.

Но если `promo.amount` приходит как строка, JavaScript может выполнить не сложение чисел, а склейку строк. Из-за этого баланс изменяется неправильно.

Дополнительно проблема усиливалась тем, что баланс увеличивался до полной проверки корректности промокода, а затем приложение пыталось откатить изменение.

## Ход решения

### 1. Анализ приложения

Сначала я изучила интерфейс магазина и поняла, что для получения ответа нужно оформить заказ на специальный товар.

В исходных файлах приложения был найден товар с отдельным идентификатором:

```javascript
{
  id: 'flag',
  name: 'Summit to Talk About',
  price: 31337
}
```

Это означало, что нужно добиться успешной покупки товара с `id: 'flag'`.

### 2. Анализ проверки заказа

В логике завершения заказа была проверка: если среди купленных товаров есть товар `flag`, то приложение добавляет итоговый ответ.

Упрощённо это выглядело так:

```javascript
if (items.some((item) => item.id === 'flag' && item.quantity >= 1)) {
  // выводится итоговый ответ
}
```

Значит, основная задача — получить достаточный баланс и оформить заказ.

### 3. Поиск ошибки в промокоде

Дальше я изучила обработку промокода и заметила опасный порядок действий:

```javascript
session.balance += promo.amount;
```

Баланс увеличивался до того, как промокод полностью проверялся.

Если передать значение `amount` как строку, JavaScript начинает работать не так, как ожидалось. Например:

```javascript
5000 + "5000"
```

Результат будет не `10000`, а строка:

```text
50005000
```

А при попытке откатить баланс через вычитание JavaScript снова приводит значение к числу. Из-за этого баланс может стать намного больше ожидаемого.

### 4. Использование ошибки

Через DevTools и `fetch` можно было отправить запросы к API приложения.

Сначала применялся обычный промокод, а затем промокод с изменённым типом данных, где `amount` передавался строкой.

В публичной версии writeup реальные значения промокодов и итоговый флаг не указываются:

```text
promo: [redacted]
flag: flag{...}
```

### 5. Добавление скрытого товара в корзину

После увеличения баланса можно было добавить нужный товар в корзину через API:

```javascript
await fetch('/api/cart', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    chocolateId: 'flag',
    quantity: 1
  })
}).then(r => r.json())
```

### 6. Оформление заказа

Затем заказ оформлялся через API:

```javascript
await fetch('/api/checkout', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  }
}).then(r => r.json())
```

После этого можно было получить результат:

```javascript
await fetch('/api/completed')
  .then(r => r.json())
  .then(console.log)
```

## Почему это сработало

Приложение не проверяло тип данных у значения промокода. Из-за этого строка попадала туда, где ожидалось число.

В JavaScript это особенно опасно, потому что оператор `+` может выполнять как сложение, так и склейку строк. Если приложение работает с балансом, ценами или оплатой, такие ошибки могут привести к серьёзным последствиям.

Также в задании была ошибка в порядке действий: баланс изменялся до полной проверки промокода.
