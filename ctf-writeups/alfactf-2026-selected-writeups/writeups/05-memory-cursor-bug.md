# Задание 5 — Углеродный след

> **Альфа CTF 2026**  
> Категория: **Pwn / Baby / Memory**  
> Статус: решено  
> Формат: краткий writeup для портфолио

## Описание

В задании был выдан бинарный файл и доступ к удалённому сервису по SSH. После запуска программы появлялась форма входа с полями логина и пароля.

На первый взгляд нужно было узнать пароль администратора. Но пароль каждый раз генерировался случайно, поэтому обычный подбор не подходил.

## Основная идея

Уязвимость была связана с тем, что курсор в поле пароля можно было двигать влево и вправо без проверки границ.

Когда пользователь вводил символ, программа записывала его по адресу:

```text
password + cursor
```

Если увести курсор слишком далеко влево, ввод начинал записываться не в поле `password`, а в соседнюю область памяти. Там находилось значение `admin_password`.

То есть можно было перезаписать случайный пароль администратора на известное значение.

## Ход решения

### 1. Анализ логики входа

В программе была логика проверки:

```text
username должен быть равен admin-пользователю
password должен совпадать с admin_password
```

Проблема была в том, что `admin_password` каждый раз создавался случайно. Поэтому просто угадать его было нельзя.

### 2. Поиск ошибки в работе с курсором

Во время ввода пароля можно было перемещать курсор стрелками влево и вправо.

Но программа не проверяла, вышел ли курсор за границы поля ввода. Поэтому при сильном сдвиге влево ввод начинал попадать в память до буфера `password`.

### 3. Перезапись соседней переменной

Так как рядом в памяти находилось значение `admin_password`, можно было сдвинуть курсор назад и записать туда известную строку.

В публичной версии writeup точные данные подключения и пароль не указываются:

```text
host: [redacted]
login: [redacted]
password: [redacted]
```

Логика действий была такой:

```text
1. Ввести нужный логин.
2. В поле пароля сдвинуть курсор влево до области admin_password.
3. Записать известную строку.
4. Вернуть курсор обратно в область password.
5. Ввести ту же строку как обычный пароль.
```

### 4. Успешный вход

После перезаписи `admin_password` и ввода такого же значения в поле `password` проверка прошла успешно.

Флаг в публичной версии writeup не указывается:

```text
flag{...}
```

## Почему это сработало

Программа доверяла позиции курсора и не проверяла границы буфера. Из-за этого пользовательский ввод мог записываться не только в предназначенное поле, но и в соседние данные в памяти.

Это типичная ошибка работы с памятью: если не контролировать границы записи, можно повредить или изменить важные переменные программы.

## Использованные инструменты

- SSH
- интерактивный терминал
- анализ поведения программы
- базовое понимание памяти
- работа с вводом и перемещением курсора


Задание показало базовую идею уязвимостей работы с памятью: если программа не проверяет границы ввода, пользователь может записать данные за пределы ожидаемого буфера.  
В этом случае это позволило перезаписать случайный пароль администратора на известное значение и пройти проверку входа.
